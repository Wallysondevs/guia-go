Channels

Um channel (canal) é um cano por onde uma goroutine manda valores para outra. Ele resolve dois problemas de uma vez: passa dados e faz uma goroutine esperar a outra. É o jeito “Go” de coordenar concorrência: não comunique compartilhando memória; compartilhe memória comunicando.

Você vai aprender
  • Criar um canal com make(chan T), enviar com ch <- v e receber com <-ch.
  • A diferença entre canal sem buffer e com buffer (make(chan T, n)).
  • Fechar com close e percorrer com for … range.
  • Os erros reais: all goroutines are asleep - deadlock! e send on closed channel.

A ideia: um cano entre duas goroutines

Quem envia (ch <- v) coloca um valor numa ponta. Quem recebe (<-ch) tira na outra. Num canal sem buffer, o envio fica parado até alguém receber, e o recebimento fica parado até alguém enviar. É um aperto de mão: os dois lados se encontram.

1. Enviar e receber

package main

import "fmt"

func main() {
	ch := make(chan string)

	go func() {
		ch <- "mensagem da goroutine"
	}()

	msg := <-ch
	fmt.Println("recebi:", msg)
}
$ go run .
recebi: mensagem da goroutine

Diferente da aula de goroutines, aqui não precisamos de time.Sleep: o msg := <-ch faz o main esperar até a goroutine enviar. A espera vem de graça com o canal.

make(chan string)
cria um canal que transporta valores do tipo string.
ch <- "…"
envia um valor para o canal (a seta aponta para dentro do canal).
<-ch
recebe um valor do canal (a seta sai de dentro do canal).

2. Canal com buffer

Com um número no make, o canal ganha um buffer: aceita até aquela quantidade de valores sem ninguém receber. len diz quantos estão guardados; cap, quantos cabem:

package main

import "fmt"

func main() {
	ch := make(chan int, 3)
	ch <- 10
	ch <- 20
	fmt.Println("len:", len(ch), "cap:", cap(ch))
	fmt.Println(<-ch)
	fmt.Println(<-ch)
	fmt.Println("len:", len(ch), "cap:", cap(ch))
}
$ go run .
len: 2 cap: 3
10
20
len: 0 cap: 3

Os valores saem na mesma ordem em que entraram (primeiro a entrar, primeiro a sair). Aqui tudo roda numa goroutine só: funciona porque o buffer tinha espaço. Com o buffer cheio, o próximo envio ficaria esperando.

3. Fechar e percorrer com range

Quem envia pode avisar “acabou” com close(ch). Do outro lado, o for v := range ch recebe até o canal ser fechado e esvaziado. O tipo chan<- int no parâmetro diz que a função só envia:

package main

import "fmt"

func produtor(ch chan<- int) {
	for i := 1; i <= 3; i++ {
		ch <- i * i
	}
	close(ch)
}

func main() {
	ch := make(chan int)
	go produtor(ch)
	for v := range ch {
		fmt.Println("valor:", v)
	}
	v, ok := <-ch
	fmt.Println("depois de fechado:", v, ok)
}
$ go run .
valor: 1
valor: 4
valor: 9
depois de fechado: 0 false

Depois de fechado e vazio, receber não trava: devolve o valor zero do tipo (0) e ok igual a false. É assim que se descobre que um canal foi fechado.

Quem fecha é quem envia

Feche o canal do lado que envia, e só quando não houver mais nada para mandar. Quem recebe nunca deveria fechar. Também não é obrigatório fechar todo canal: feche quando o outro lado precisa saber que acabou (como no range).

Quando dá errado

Deadlock: todo mundo esperando

Num canal sem buffer, enviar no main sem nenhuma goroutine para receber trava para sempre. O Go percebe que nenhuma goroutine pode avançar e derruba o programa:

package main

import "fmt"

func main() {
	ch := make(chan int)
	ch <- 1
	fmt.Println(<-ch)
}
$ go run .
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [chan send]:
main.main()
	/home/ana/projetos/go-nivel3/channels/deadlock/main.go:7 +0x36
exit status 2

Leia de cima para baixo: o erro (all goroutines are asleep - deadlock!), qual goroutine travou e onde (goroutine 1 [chan send], ou seja, parada num envio) e a linha do arquivo (main.go:7). O exit status 2 é o go run contando que o programa terminou com erro.

Enviar num canal fechado

Depois do close, qualquer envio é um panic:

package main

func main() {
	ch := make(chan int, 1)
	close(ch)
	ch <- 1
}
$ go run .
panic: send on closed channel

goroutine 1 [running]:
main.main()
	/home/ana/projetos/go-nivel3/channels/fechado/main.go:6 +0x3a
exit status 2

Resumo

  • Canais passam valores entre goroutines e, de quebra, fazem uma esperar a outra.
  • Sem buffer, envio e recebimento se encontram; com buffer, o envio só espera quando está cheio.
  • Quem envia fecha com close; quem recebe usa range ou v, ok := <-ch.
  • Todo mundo esperando dá all goroutines are asleep - deadlock!; enviar em canal fechado dá panic.
