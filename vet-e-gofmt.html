go vet e gofmt

Duas ferramentas que vêm com o Go e que todo projeto usa. O gofmt arruma a formatação do código: recuo com tabulação, espaços, linhas em branco. Assim todo código Go tem a mesma cara, e ninguém discute estilo. O go vet procura erros que compilam, mas quase certamente são bugs, como um %d recebendo texto.

Você vai aprender
  • Listar, comparar e corrigir a formatação com gofmt -l, -d e -w.
  • Rodar o go vet e ler os avisos reais (formato do Printf e cópia de Mutex).
  • Por que um código que compila ainda pode estar errado.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), dentro de ~/projetos/go-nivel3 da usuária fictícia ana, no computador notebook. O gofmt e o go vet não escrevem nada quando está tudo certo: saída vazia é boa notícia. As mensagens do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída.

1. Um código feio que funciona

Este arquivo compila e roda, mas está todo torto:

package main
import "fmt"
func main(){
x:=10
  if x>5 {
fmt.Println("x é grande")
    }
}
$ go run .
x é grande

gofmt -l: quem está fora do padrão?

O -l (de list) só lista os arquivos que o gofmt mudaria:

$ gofmt -l .
main.go

gofmt -d: o que mudaria?

O -d (de diff) mostra as mudanças sem gravar nada. Linhas com - saem, linhas com + entram:

$ gofmt -d main.go
diff main.go.orig main.go
+++ main.go
@@ -1,8 +1,10 @@
 package main
+
 import "fmt"
-func main(){
-x:=10
-  if x>5 {
-fmt.Println("x é grande")
-    }
+
+func main() {
+	x := 10
+	if x > 5 {
+		fmt.Println("x é grande")
+	}
 }

As linhas main.go.orig e main.go do cabeçalho são só os rótulos do “antes” e do “depois” que o próprio gofmt escreve: não existe arquivo .orig na pasta.

gofmt -w: corrija

O -w (de write) grava a versão arrumada no próprio arquivo. Depois disso, o -l não lista mais nada:

$ gofmt -w main.go
$ gofmt -l .
$ cat main.go
package main

import "fmt"

func main() {
	x := 10
	if x > 5 {
		fmt.Println("x é grande")
	}
}

Repare no que mudou: linhas em branco depois do package e do import, espaço antes da {, espaços em volta de := e >, e recuo com tabulação. Quase todo editor com a extensão de Go roda o gofmt ao salvar.

go fmt e gofmt

go fmt ./... é um atalho que roda gofmt -l -w em todos os pacotes do módulo. No dia a dia, é o que mais se usa.

2. go vet: compila, mas está errado

Aqui o %d (número) recebe nome, que é texto. O Go compila e roda, mas a saída sai estranha:

package main

import "fmt"

func main() {
	nome := "Ana"
	idade := 30
	fmt.Printf("%d tem %d anos\n", nome, idade)
}
$ go run .
%!d(string=Ana) tem 30 anos

O %!d(string=Ana) é o jeito do fmt dizer “pediram %d, mas veio uma string com o valor Ana”. O go vet pega isso antes de rodar:

$ go vet .
main.go:8:14: fmt.Printf format %d has arg nome of wrong type string

O aviso aponta arquivo, linha e coluna (main.go:8:14) e diz exatamente o problema. Para checar o módulo inteiro, use ./...:

$ go vet ./...
main.go:8:14: fmt.Printf format %d has arg nome of wrong type string
go vet
roda dezenas de verificações (as “análises”) sobre o código.
.
o pacote da pasta atual.
./...
a pasta atual e todas as subpastas do módulo.

Cópia de Mutex

Um sync.Mutex não pode ser copiado (aula sync). Passar a struct por valor copia a tranca junto. Compila, mas o go vet reclama:

package main

import (
	"fmt"
	"sync"
)

type Contador struct {
	mu    sync.Mutex
	valor int
}

func mostrar(c Contador) {
	fmt.Println(c.valor)
}

func main() {
	var c Contador
	mostrar(c)
}
$ go build . && echo compilou
compilou
$ go vet .
main.go:13:16: mostrar passes lock by value: exemplo/copia.Contador contains sync.Mutex
main.go:19:10: call of mostrar copies lock value: exemplo/copia.Contador contains sync.Mutex

São dois avisos: a função recebe a tranca por valor (linha 13) e a chamada copia a tranca (linha 19). A correção é passar um ponteiro: func mostrar(c *Contador) e mostrar(&c).

Quando dá errado

“Mas compilou!”

O compilador só garante que o código é Go válido. O go vet procura o que é válido mas suspeito. Por isso projetos sérios rodam os dois antes de cada commit, e o go test já roda uma parte do go vet automaticamente.

O gofmt -d sai com código 1

Quando há diferença, o gofmt -d termina com código de saída 1 (na coleta, também foi assim). Não é erro de execução: é o jeito de scripts saberem que há algo a formatar.

Referência rápida

Você digitaO que faz
gofmt -l .Lista os arquivos fora do padrão.
gofmt -d arquivo.goMostra as mudanças, sem gravar.
gofmt -w arquivo.goGrava a versão formatada.
go fmt ./...Formata todos os pacotes do módulo.
go vet . / go vet ./...Procura bugs prováveis no pacote / no módulo todo.

Resumo

  • gofmt deixa todo código Go com a mesma formatação: -l lista, -d mostra, -w grava.
  • go vet acha bugs que compilam, como formato errado no Printf e cópia de Mutex.
  • Saída vazia dos dois é boa notícia.
