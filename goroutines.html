Goroutines

Uma goroutine é uma função rodando “ao lado” do resto do programa. Basta escrever go antes da chamada. Elas são leves (dá para ter milhares) e são a base de toda a concorrência em Go. Nesta aula você vê o detalhe que mais pega quem começa: o programa não espera as goroutines por conta própria.

Você vai aprender
  • Como iniciar uma goroutine com go funcao() e com go func() { … }().
  • Por que o main pode terminar antes da goroutine, e a saída sumir.
  • Por que a ordem das linhas muda de uma execução para outra.
  • Como contar goroutines com runtime.NumGoroutine.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), dentro de ~/projetos/go-nivel3 da usuária fictícia ana, no computador notebook. Em concorrência, a ordem das linhas pode mudar a cada execução e de um computador para outro: o que aparece aqui é uma das ordens possíveis, colhida de verdade. As mensagens do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída.

A ideia: cozinhar várias coisas ao mesmo tempo

Pense numa cozinha. O main é você. Cada go é um ajudante que começa uma tarefa e segue sozinho. Se você fecha a cozinha (o main termina), todos os ajudantes vão embora no mesmo instante, tenham terminado ou não.

1. A primeira goroutine (e o susto)

Coloque go antes da chamada de diga:

package main

import "fmt"

func diga(msg string) {
	fmt.Println(msg)
}

func main() {
	go diga("olá da goroutine")
	fmt.Println("fim do main")
}

Rodamos três vezes. Nas três, só apareceu a linha do main:

$ go run .
fim do main
$ go run .
fim do main
$ go run .
fim do main

O go diga(…) não espera nada: ele agenda a função e volta na hora. O main escreve fim do main e termina. Quando o main termina, o programa inteiro acaba, e a goroutine não teve tempo de escrever.

2. Dando tempo com time.Sleep

O jeito mais simples (e mais tosco) de ver a goroutine trabalhar é fazer o main dormir um pouco:

package main

import (
	"fmt"
	"time"
)

func diga(msg string) {
	fmt.Println(msg)
}

func main() {
	go diga("olá da goroutine")
	time.Sleep(100 * time.Millisecond)
	fmt.Println("fim do main")
}
$ go run .
olá da goroutine
fim do main
Sleep não é sincronização

O time.Sleep aqui só serve para a aula. Ele “chuta” um tempo: se a goroutine demorar mais que isso, a saída some de novo. O jeito certo de esperar é com channels ou com sync.WaitGroup, que você vê nas próximas aulas.

3. Várias goroutines: a ordem muda

Agora cinco goroutines, cada uma escrevendo o seu número. Usamos uma função anônima, go func() { … }(); os parênteses do fim chamam a função:

package main

import (
	"fmt"
	"time"
)

func main() {
	for i := 1; i <= 5; i++ {
		go func() {
			fmt.Println("goroutine", i)
		}()
	}
	time.Sleep(100 * time.Millisecond)
	fmt.Println("fim do main")
}

Três execuções seguidas, três ordens diferentes:

$ go run .
goroutine 5
goroutine 1
goroutine 2
goroutine 3
goroutine 4
fim do main
$ go run .
goroutine 5
goroutine 4
goroutine 2
goroutine 3
goroutine 1
fim do main
$ go run .
goroutine 5
goroutine 2
goroutine 3
goroutine 4
goroutine 1
fim do main

Quem decide a ordem é o escalonador do Go, que distribui as goroutines entre os núcleos do processador. Repare que o 5 saiu primeiro nas três vezes: a última goroutine criada costuma ser a próxima a rodar. Isso é um detalhe interno, não uma promessa. Nunca escreva código que dependa da ordem das goroutines.

Cada volta tem o seu i

Desde o Go 1.22, cada volta do for cria uma variável i nova. Por isso cada goroutine viu o seu próprio número (1 a 5). Em versões antigas, todas podiam ver o mesmo valor final. Se você ler código antigo com i := i dentro do for, era para evitar esse problema.

4. Contando goroutines

O pacote runtime mostra quantos núcleos o Go enxerga e quantas goroutines existem agora. O próprio main já é uma goroutine:

package main

import (
	"fmt"
	"runtime"
	"time"
)

func main() {
	fmt.Println("CPUs:", runtime.NumCPU())
	fmt.Println("goroutines no início:", runtime.NumGoroutine())
	for i := 0; i < 3; i++ {
		go time.Sleep(time.Second)
	}
	fmt.Println("goroutines depois do go:", runtime.NumGoroutine())
}
$ go run .
CPUs: 8
goroutines no início: 1
goroutines depois do go: 4

Começa com 1 (o main). Depois de três go time.Sleep(…), são 4. O número de CPUs depende do seu computador: aqui eram 8.

go
palavra-chave que inicia a chamada numa goroutine nova e volta na hora, sem esperar.
func() { … }
uma função anônima, sem nome, escrita ali mesmo.
()
os parênteses do fim chamam a função. Sem eles, o Go reclama.

Quando dá errado

A saída da goroutine “sumiu”

É o caso da seção 1: o main terminou primeiro. Não há mensagem de erro, a linha simplesmente não aparece. A correção é fazer o main esperar, com channel ou WaitGroup.

Ordem diferente da do livro

Se as suas linhas saírem em outra ordem que a desta página, está tudo certo: em concorrência isso é normal. Por isso as missões abaixo conferem se cada linha apareceu, e não em que ordem.

Referência rápida

Você escreveO que faz
go f(x)Roda f(x) numa goroutine nova e segue sem esperar.
go func() { … }()Roda uma função anônima numa goroutine.
time.Sleep(d)Pausa a goroutine atual. Só para testes, não para sincronizar.
runtime.NumGoroutine()Quantas goroutines existem agora (o main conta).
runtime.NumCPU()Quantos núcleos o Go enxerga.

Missão: faça cada Println rodar numa goroutine própria, com go func() {{ … }}(). A ordem das três linhas pode sair diferente a cada execução: a missão só confere se as três apareceram.

package main

import (
	"fmt"
	"time"
)

func main() {
	for i := 1; i <= 3; i++ {
		// rode o Println abaixo numa goroutine
		fmt.Println("trabalhador", i)
	}
	time.Sleep(100 * time.Millisecond)
}

package main

import (
	"fmt"
	"time"
)

func main() {
	for i := 1; i <= 3; i++ {
		go func() {
			fmt.Println("trabalhador", i)
		}()
	}
	time.Sleep(100 * time.Millisecond)
}

trabalhador 3
trabalhador 1
trabalhador 2

Resumo

  • go f() roda f numa goroutine e volta na hora, sem esperar.
  • Quando o main termina, o programa acaba, mesmo com goroutines no meio do trabalho.
  • A ordem entre goroutines não é garantida. Para esperar, use channels ou sync.WaitGroup, não time.Sleep.
