Servidor HTTP (net/http)

Go já vem com um servidor web completo na biblioteca padrão, o pacote net/http. Sem instalar nada, você escreve um servidor em vinte linhas, com rotas por método (GET, POST) e pedaços variáveis no caminho (/ola/{nome}). Nesta aula o servidor roda só no seu computador e você o testa com o curl.

Você vai aprender
  • Registrar rotas com http.HandleFunc, inclusive "GET /ola/{nome}" e r.PathValue.
  • Subir o servidor com http.ListenAndServe em 127.0.0.1, numa porta alta.
  • Ler as respostas reais com curl -i: 200, 404 e 405.
  • Responder JSON e encerrar o servidor com Ctrl+C.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), dentro de ~/projetos/go-nivel3 da usuária fictícia ana, no computador notebook. O servidor ouviu só em 127.0.0.1 (o próprio computador), na porta 8089, e foi encerrado no fim de cada teste. As linhas de log (hora local) e o cabeçalho Date (sempre em GMT, por isso três horas à frente) trazem a data e a hora da coleta; no seu computador serão as suas. As mensagens do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída.

A ideia: um balcão de atendimento

O servidor é um balcão. Cada rota é um guichê com uma placa (“GET /ola/{nome}”). Quando chega um pedido, o Go olha a placa que combina e chama a função daquele guichê, o handler. O handler escreve a resposta no http.ResponseWriter.

1. O servidor

package main

import (
	"fmt"
	"log"
	"net/http"
)

func inicio(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "Bem-vindo ao servidor Go!")
}

func ola(w http.ResponseWriter, r *http.Request) {
	nome := r.PathValue("nome")
	fmt.Fprintf(w, "Olá, %s!\n", nome)
}

func main() {
	http.HandleFunc("GET /{$}", inicio)
	http.HandleFunc("GET /ola/{nome}", ola)

	endereco := "127.0.0.1:8089"
	log.Println("ouvindo em http://" + endereco)
	log.Fatal(http.ListenAndServe(endereco, nil))
}
"GET /{$}"
só o caminho / exato, só com GET. Sem o {$}, / pegaria qualquer caminho.
"GET /ola/{nome}"
um pedaço variável do caminho, lido com r.PathValue("nome").
w http.ResponseWriter
onde você escreve a resposta (dá para usar com fmt.Fprintln).
r *http.Request
o pedido: método, caminho, cabeçalhos, corpo.
http.ListenAndServe(endereço, nil)
abre a porta e atende para sempre. Só volta se der erro.

Rode num terminal. Ele escreve a linha do log e fica esperando pedidos (o terminal fica “preso”, é normal):

$ go run .
2026/11/21 09:13:42 ouvindo em http://127.0.0.1:8089

2. Testando com o curl

Abra outro terminal e faça pedidos. O -s deixa o curl quieto; o -i mostra também a linha de status e os cabeçalhos:

$ curl -s http://127.0.0.1:8089/
Bem-vindo ao servidor Go!
$ curl -s http://127.0.0.1:8089/ola/Ana
Olá, Ana!
$ curl -i -s http://127.0.0.1:8089/ola/Ana
HTTP/1.1 200 OK
Date: Sat, 21 Nov 2026 12:13:44 GMT
Content-Length: 11
Content-Type: text/plain; charset=utf-8

Olá, Ana!

A primeira linha, HTTP/1.1 200 OK, diz que deu certo. O Go preencheu sozinho o Content-Type (adivinhou texto em UTF-8) e o Content-Length: são 11 bytes, porque o á ocupa dois bytes em UTF-8, mais a quebra de linha.

Caminho que não existe e método errado

$ curl -i -s http://127.0.0.1:8089/nada
HTTP/1.1 404 Not Found
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Sat, 21 Nov 2026 12:13:44 GMT
Content-Length: 19

404 page not found
$ curl -i -s -X POST http://127.0.0.1:8089/ola/Ana
HTTP/1.1 405 Method Not Allowed
Allow: GET, HEAD
Content-Type: text/plain; charset=utf-8
X-Content-Type-Options: nosniff
Date: Sat, 21 Nov 2026 12:13:44 GMT
Content-Length: 19

Method Not Allowed

Para um caminho sem rota, o Go responde 404 Not Found. Para a rota certa com o método errado (POST numa rota GET), responde 405 Method Not Allowed e ainda avisa no cabeçalho Allow que ali só vale GET, HEAD. Você não escreveu nada disso: vem pronto do roteador do net/http.

3. Respondendo JSON

Para uma API, defina o cabeçalho Content-Type e use o encoding/json (aula JSON) direto no w:

package main

import (
	"encoding/json"
	"log"
	"net/http"
)

type Status struct {
	Servico string `json:"servico"`
	Ok      bool   `json:"ok"`
}

func status(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(Status{Servico: "guia-go", Ok: true})
}

func main() {
	http.HandleFunc("GET /status", status)
	log.Fatal(http.ListenAndServe("127.0.0.1:8089", nil))
}
$ curl -i -s http://127.0.0.1:8089/status
HTTP/1.1 200 OK
Content-Type: application/json
Date: Sat, 21 Nov 2026 12:13:48 GMT
Content-Length: 32

{"servico":"guia-go","ok":true}

4. Encerrando o servidor

Volte ao terminal do servidor e aperte Ctrl+C. Isso manda ao programa o sinal de interrupção (SIGINT). Na coleta, para não depender de alguém apertando a tecla, mandamos o mesmo sinal com timeout -s INT 3, três segundos depois de subir. O go run avisa que o programa terminou por causa do sinal:

$ timeout -s INT 3 go run .
2026/11/21 09:13:56 ouvindo em http://127.0.0.1:8089
signal: interrupt
Por que 127.0.0.1 e porta alta?

Com 127.0.0.1, só o seu próprio computador acessa o servidor: ninguém da rede chega nele. Escrever só ":8089" abriria a porta para a rede inteira. Portas acima de 1024 (como 8089) não pedem permissão de administrador no Linux.

Quando dá errado

Porta ocupada

Se já há um programa ouvindo na mesma porta (por exemplo, um servidor que você esqueceu aberto noutro terminal), o ListenAndServe volta na hora com erro, e o log.Fatal escreve e encerra:

$ go run .
2026/11/21 09:13:45 ouvindo em http://127.0.0.1:8089
2026/11/21 09:13:45 listen tcp 127.0.0.1:8089: bind: address already in use
exit status 1

A mensagem real é bind: address already in use (endereço já em uso). Feche o outro servidor com Ctrl+C ou troque a porta.

O curl não conecta

Com o servidor desligado, o curl -s não mostra nada (o -s cala até os erros). Acrescente o -S para ver o motivo:

$ curl -s http://127.0.0.1:8089/
$ curl -sS http://127.0.0.1:8089/
curl: (7) Failed to connect to 127.0.0.1 port 8089 after 0 ms: Could not connect to server

O Could not connect to server quer dizer que ninguém está ouvindo naquela porta. Confira se o Terminal 1 ainda está com o servidor no ar.

Missão: acrescente a rota GET /tchau, que responde Até logo!. Suba o servidor com go run . num terminal e, noutro, rode curl -s http://127.0.0.1:8089/tchau. Cole a resposta do curl e depois encerre o servidor com Ctrl+C.

package main

import (
	"fmt"
	"log"
	"net/http"
)

func main() {
	http.HandleFunc("GET /{$}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprintln(w, "Bem-vindo ao servidor Go!")
	})
	// crie aqui a rota GET /tchau, que responde "Até logo!"
	log.Fatal(http.ListenAndServe("127.0.0.1:8089", nil))
}

Resumo

  • net/http já traz servidor e roteador: http.HandleFunc("GET /caminho", f) e http.ListenAndServe.

  • Para estudar, ouça em 127.0.0.1 numa porta alta e encerre com Ctrl+C.
  • Porta já usada dá bind: address already in use.
