context

O pacote context leva um recado “pode parar” para todas as goroutines de uma tarefa. Esse recado pode vir de um prazo (“no máximo 200 ms”) ou de um cancelamento manual. Servidores HTTP, bancos de dados e clientes de rede da biblioteca padrão aceitam um context.Context justamente para isso.

Você vai aprender
  • Criar um contexto com prazo, context.WithTimeout, e com cancelamento, context.WithCancel.
  • Ouvir o recado com <-ctx.Done() e ler o motivo com ctx.Err().
  • As duas mensagens reais: context deadline exceeded e context canceled.
  • Por que sempre chamar cancel(), de preferência com defer.

A ideia: um apito para todo mundo parar

Pense num juiz com um apito. Quando ele apita (prazo esgotado ou cancelamento), todos os jogadores que estão ouvindo param. O ctx.Done() é o ouvido: um canal que se fecha quando o apito soa.

1. Prazo com WithTimeout

Um trabalho que levaria 2 segundos, mas com prazo de 200 ms. A função escuta os dois canais com select:

package main

import (
	"context"
	"fmt"
	"time"
)

func trabalhoLento(ctx context.Context) error {
	select {
	case <-time.After(2 * time.Second):
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
	defer cancel()

	inicio := time.Now()
	err := trabalhoLento(ctx)
	fmt.Println("erro:", err)
	fmt.Println("demorou menos de 1s:", time.Since(inicio) < time.Second)
}
$ go run .
erro: context deadline exceeded
demorou menos de 1s: true

O prazo venceu primeiro, o ctx.Done() fechou e ctx.Err() explicou o motivo: context deadline exceeded (prazo do contexto excedido). O programa não esperou os 2 segundos.

context.Background()
o contexto vazio, raiz de todos os outros.
WithTimeout(pai, 200*time.Millisecond)
cria um filho que “apita” sozinho depois de 200 ms.
cancel
função que apita na hora e libera os recursos do contexto.
defer cancel()
garante que o cancel é chamado quando a função terminar.

2. Cancelamento manual com WithCancel

Aqui uma goroutine “vigia” trabalha em voltas de 50 ms até o main chamar cancel():

package main

import (
	"context"
	"fmt"
	"time"
)

func vigia(ctx context.Context, fim chan<- string) {
	for {
		select {
		case <-ctx.Done():
			fim <- "vigia parou: " + ctx.Err().Error()
			return
		default:
			time.Sleep(50 * time.Millisecond)
		}
	}
}

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	fim := make(chan string)
	go vigia(ctx, fim)

	time.Sleep(150 * time.Millisecond)
	cancel()
	fmt.Println(<-fim)
}
$ go run .
vigia parou: context canceled

Depois do cancel(), o ctx.Done() fechou, o select da vigia caiu nesse case e ela saiu, avisando pelo canal fim. O motivo agora é context canceled.

3. Conferindo o motivo com errors.Is

ctx.Err() devolve um de dois erros prontos do pacote: context.DeadlineExceeded ou context.Canceled. Compare com errors.Is:

package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
	defer cancel()

	<-ctx.Done()
	fmt.Println(ctx.Err())
	fmt.Println(errors.Is(ctx.Err(), context.DeadlineExceeded))

	ctx2, cancel2 := context.WithCancel(context.Background())
	cancel2()
	fmt.Println(ctx2.Err())
	fmt.Println(errors.Is(ctx2.Err(), context.Canceled))
}
$ go run .
context deadline exceeded
true
context canceled
true

Antes de o contexto terminar, ctx.Err() devolve nil. Por isso o padrão é sempre esperar o Done() (ou checar o Err()) antes de decidir.

Quando dá errado

Esquecer o cancel

O WithTimeout e o WithCancel devolvem um cancel que precisa ser chamado, senão os recursos do contexto ficam presos até o prazo. O go vet avisa quando o cancel é jogado fora com _. O programa abaixo compila e roda, mas o go vet reclama:

package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, _ := context.WithTimeout(context.Background(), time.Second)
	fmt.Println(ctx.Err())
}
$ go vet .
main.go:10:7: the cancel function returned by context.WithTimeout should be called, not discarded, to avoid a context leak

A correção é guardar o cancel e escrever defer cancel() logo na linha de baixo.

A goroutine que não escuta

O contexto não “mata” ninguém: ele só fecha o canal Done(). Se a goroutine nunca olha para o ctx.Done(), ela continua rodando. Toda função demorada que recebe um ctx precisa checá-lo.

Missão: chame cancel() (numa linha própria, não só no defer) e espere o <-ctx.Done() antes do Println. Do jeito que está, o programa mostra estado: <nil> (rodamos para conferir); com a correção, mostra o motivo do cancelamento.

package main

import (
	"context"
	"fmt"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()

	// cancele o contexto antes de esperar por ele
	fmt.Println("estado:", ctx.Err())
}

Resumo

  • WithTimeout termina sozinho; WithCancel termina quando você chama cancel().
  • Quem trabalha escuta <-ctx.Done() e lê o motivo em ctx.Err().
  • As mensagens reais são context deadline exceeded e context canceled.
  • Sempre defer cancel(), e o contexto vai como primeiro parâmetro das funções.
