Build Cruzado (GOOS e GOARCH)

Uma das coisas mais legais do Go: do seu Linux você gera um executável para Windows, para Mac ou para um Raspberry Pi, sem instalar nada a mais. Basta dizer o sistema (GOOS) e a arquitetura do processador (GOARCH) na hora do go build. Nesta aula você gera quatro executáveis e usa o comando file para provar o que cada um é.

Você vai aprender
  • O que são GOOS e GOARCH e como ver os valores atuais com go env.
  • Gerar executáveis para Windows, macOS e Linux ARM com GOOS=… GOARCH=… go build.
  • Conferir o resultado com file e listar as combinações com go tool dist list.
  • Os erros reais: Exec format error e unsupported GOOS/GOARCH pair.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), dentro de ~/projetos/go-nivel3 da usuária fictícia ana, no computador notebook. O comando file vem na maioria dos Linux (se faltar, instale o pacote file). Os BuildID que ele mostra são impressões digitais de cada compilação: no seu computador serão outros, assim como os tamanhos exatos dos arquivos. As mensagens do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída.

1. O programa e o ambiente atual

Um programa que diz para qual sistema e arquitetura foi compilado, usando o pacote runtime:

package main

import (
	"fmt"
	"runtime"
)

func main() {
	fmt.Printf("Olá de %s/%s!\n", runtime.GOOS, runtime.GOARCH)
}

Sem dizer nada, o Go compila para a máquina onde está rodando. O go env mostra quais são:

$ go env GOOS GOARCH
linux
amd64
$ go build -o ola . && ./ola
Olá de linux/amd64!

2. Compilando para outros sistemas

Escreva as variáveis antes do comando, na mesma linha. Elas valem só para aquele comando. Quando dá certo, o go build não escreve nada:

$ GOOS=windows GOARCH=amd64 go build -o ola.exe .
$ GOOS=darwin GOARCH=arm64 go build -o ola-mac .
$ GOOS=linux GOARCH=arm64 go build -o ola-arm64 .
$ ls -l ola ola.exe ola-mac ola-arm64

Dois extras úteis

CGO_ENABLED=0 desliga o uso de código C e garante um executável que não depende de nada do sistema (aqui ele já saía assim). E -ldflags='-s -w' tira as informações de depuração, deixando o arquivo menor:

$ CGO_ENABLED=0 go build -o ola-estatico . && file ola-estatico
ola-estatico: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, Go BuildID=Q70h7ZQj_E8vEcUVbUwj/jEAgOdsDCG_n38NNZbEX/J5t-syxyTwGVfR59o9X1/KGiu9Eu5WHk7yqeKmh79, BuildID[sha1]=a96445b3db029817cb997581a114e7970de9a2d1, with debug_info, not stripped

Quando dá errado

Rodar o executável de outro sistema

Um executável de Windows ou de ARM não roda neste Linux x86-64. Quem reclama é o próprio shell, o bash:

$ ./ola.exe
bash: ./ola.exe: cannot execute binary file: Exec format error
$ ./ola-arm64
bash: ./ola-arm64: cannot execute binary file: Exec format error

Exec format error quer dizer “não sei executar este formato”. O arquivo está certo; a máquina é que é outra.

Nome de sistema errado

Um erro de digitação no GOOS é recusado na hora:

$ GOOS=windowss go build -o x .
go: unsupported GOOS/GOARCH pair windowss/amd64

O Go mostra a combinação que tentou (windowss/amd64; o amd64 veio da máquina atual, porque não passamos GOARCH). Confira os nomes com go tool dist list.

No Windows, as variáveis são escritas de outro jeito

O GOOS=… go build na mesma linha é sintaxe do Bash (Linux, macOS, Git Bash, WSL). No PowerShell, use $env:GOOS="linux" e $env:GOARCH="amd64" antes do go build; no Prompt de Comando, set GOOS=linux.

Resumo

  • GOOS é o sistema, GOARCH o processador; o go env mostra os atuais.
  • GOOS=… GOARCH=… go build gera executáveis para outras plataformas, sem instalar nada.
  • O file confirma o formato; rodar o executável de outra plataforma dá Exec format error.
