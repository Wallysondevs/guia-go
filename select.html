select

O select é um switch para canais: ele espera vários canais ao mesmo tempo e segue com o primeiro que ficar pronto. Com ele você escreve tempo-limite (“desisto depois de 300 ms”) e operações que não travam.

Você vai aprender
  • Esperar dois canais e ficar com a resposta que chegar primeiro.
  • Pôr tempo-limite com time.After.
  • Tentar enviar ou receber sem travar, com default.
  • O deadlock real de um select {} vazio.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), dentro de ~/projetos/go-nivel3 da usuária fictícia ana, no computador notebook. Os exemplos usam pausas (time.Sleep) para simular trabalho lento; os tempos medidos variam um pouco a cada execução. As mensagens do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída.

A ideia: atender o primeiro telefone que tocar

Imagine dois telefones na mesa. Você fica esperando e atende o primeiro que tocar. O select faz isso com canais: cada case é um telefone.

1. O primeiro que responder

Duas goroutines: uma responde em 50 ms, outra em 500 ms. O select fica com a que chegar primeiro:

package main

import (
	"fmt"
	"time"
)

func main() {
	rapido := make(chan string)
	lento := make(chan string)

	go func() {
		time.Sleep(50 * time.Millisecond)
		rapido <- "resposta rápida"
	}()
	go func() {
		time.Sleep(500 * time.Millisecond)
		lento <- "resposta lenta"
	}()

	select {
	case msg := <-rapido:
		fmt.Println(msg)
	case msg := <-lento:
		fmt.Println(msg)
	}
}
$ go run .
resposta rápida

O select executa um case só e segue. A resposta lenta nunca é lida: o programa termina antes.

select {
espera até algum dos case poder acontecer.
case msg := <-rapido:
se der para receber de rapido, recebe em msg e roda este bloco.
case msg := <-lento:
o mesmo para lento. Se os dois estiverem prontos juntos, o Go sorteia um.

2. Tempo-limite com time.After

time.After(d) devolve um canal que recebe um valor depois do tempo d. Num case, vira um “desisto”. Aqui o trabalho leva 2 segundos, mas só esperamos 300 ms. O time antes do comando mede quanto o programa levou:

package main

import (
	"fmt"
	"time"
)

func main() {
	resultado := make(chan string)

	go func() {
		time.Sleep(2 * time.Second)
		resultado <- "terminei"
	}()

	select {
	case r := <-resultado:
		fmt.Println(r)
	case <-time.After(300 * time.Millisecond):
		fmt.Println("desisti: passou de 300ms")
	}
}
$ time go run .
desisti: passou de 300ms

real	0m0.397s
user	0m0.109s
sys	0m0.042s

O programa inteiro levou menos de meio segundo (o real), e não 2 segundos: o select desistiu em 300 ms. O resto é o tempo do go run compilar. Os números do time mudam a cada execução.

3. Sem travar: default

Com default, se nenhum case estiver pronto agora, o select roda o default e segue, sem esperar. Aqui o canal tem buffer de 1: o primeiro envio cabe, os outros não:

package main

import "fmt"

func main() {
	ch := make(chan int, 1)

	for i := 1; i <= 3; i++ {
		select {
		case ch <- i:
			fmt.Println("enviei", i)
		default:
			fmt.Println("canal cheio, pulei o", i)
		}
	}
}
$ go run .
enviei 1
canal cheio, pulei o 2
canal cheio, pulei o 3

Quando dá errado

select {} vazio

Um select sem nenhum case espera para sempre. Sem outra goroutine viva, o Go detecta o deadlock:

package main

func main() {
	select {}
}
$ go run .
fatal error: all goroutines are asleep - deadlock!

goroutine 1 [select (no cases)]:
main.main()
	/home/ana/projetos/go-nivel3/select/vazio/main.go:4 +0xf
exit status 2

Repare no motivo entre colchetes: [select (no cases)]. Em servidores, às vezes se usa select {} de propósito para segurar o main enquanto outras goroutines trabalham; sem elas, é deadlock.

time.After dentro de um laço longo

Cada chamada de time.After cria um temporizador novo. Num for que roda milhares de vezes, prefira criar um time.NewTimer ou usar context com prazo.

Missão: a goroutine demora 1 segundo. Troque o fmt.Println(<-ch) por um select que mostre a mensagem se ela chegar, ou tempo esgotado se passar de 100 ms (time.After(100 * time.Millisecond)).

package main

import (
	"fmt"
	"time"
)

func main() {
	ch := make(chan string)

	go func() {
		time.Sleep(time.Second)
		ch <- "pronto"
	}()

	// espere no máximo 100ms: use select com time.After
	fmt.Println(<-ch)
}

package main

import (
	"fmt"
	"time"
)

func main() {
	ch := make(chan string)

	go func() {
		time.Sleep(time.Second)
		ch <- "pronto"
	}()

	select {
	case msg := <-ch:
		fmt.Println(msg)
	case <-time.After(100 * time.Millisecond):
		fmt.Println("tempo esgotado")
	}
}

tempo esgotado

Missão: este programa trava, porque ninguém envia no canal. Troque o recebimento por um select com default que mostre nada no canal quando não houver valor.

package main

import "fmt"

func main() {
	ch := make(chan int)

	// receber assim trava para sempre: ninguém envia
	// troque por um select com default
	v := <-ch
	fmt.Println("recebi", v)
}

package main

import "fmt"

func main() {
	ch := make(chan int)

	select {
	case v := <-ch:
		fmt.Println("recebi", v)
	default:
		fmt.Println("nada no canal")
	}
}

nada no canal

Resumo

  • select espera vários canais e roda o primeiro case pronto.
  • case <-time.After(d) dá um tempo-limite; default evita esperar.
  • Um select {} sem outras goroutines termina em all goroutines are asleep - deadlock!.
