Módulos (go mod init)

Um módulo é o “projeto” do Go: uma pasta com um arquivo go.mod que diz o nome do projeto e a versão do Go. Todo projeto de verdade começa com go mod init, e é com o módulo que você usa vários arquivos, pacotes e testes.

Você vai aprender
  • Criar um módulo com go mod init e ler o go.mod.
  • Rodar e compilar o módulo inteiro com go run . e go build.
  • Ver um módulo com dois arquivos no mesmo pacote.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), na pasta ~/projetos da usuária fictícia ana, no computador notebook. As mensagens de erro do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída. A explicação em português vem ao lado.

1. Criando o módulo

Dentro de uma pasta vazia, rode go mod init com o nome do módulo. Para projetos pessoais, um nome curto basta; se for publicar no GitHub, o costume é usar o endereço, como github.com/ana/loja:

$ go mod init loja
go: creating new go.mod: module loja
$ cat go.mod
module loja

go 1.27.3
module loja
o nome do módulo: é o começo do caminho de import dos pacotes dele.
go 1.27.3
a versão do Go com que o módulo foi criado.

2. go run . e go build

Com o módulo criado, o ponto (.) quer dizer “o pacote desta pasta”. O go build sem argumentos gera um executável com o nome do módulo:

package main

import "fmt"

func main() {
	fmt.Println("Loja da Ana: aberta!")
}
$ go run .
Loja da Ana: aberta!
$ go build
$ ls
go.mod
loja
main.go
$ ./loja
Loja da Ana: aberta!

3. Dois arquivos, um pacote

Todos os arquivos .go da mesma pasta são o mesmo pacote e enxergam as funções uns dos outros. Crie um precos.go ao lado do main.go:

package main

import "fmt"

func main() {
	fmt.Println("Café custa", precoDoCafe(), "reais")
}
package main

func precoDoCafe() float64 {
	return 4.5
}
$ go run .
Café custa 4.5 reais

Com go run main.go o Go compilaria só um arquivo e não acharia o precoDoCafe. Com go run ., ele compila a pasta toda. Veja o erro em “Quando dá errado”.

Quando dá errado

Rodou um arquivo só

No módulo loja2, rodar só o main.go deixa o precos.go de fora:

$ go run main.go
# command-line-arguments
./main.go:6:29: undefined: precoDoCafe

A mensagem undefined: precoDoCafe quer dizer “não sei o que é isso”. Rode go run ..

O módulo já existe

Rodar go mod init de novo na mesma pasta:

$ go mod init loja
go: /home/ana/projetos/loja/go.mod already exists
Sem go.mod

Numa pasta sem módulo (a solto, só com o main.go), o go build . reclama:

$ go build .
go: go.mod file not found in current directory or any parent directory; see 'go help modules'

Referência rápida

Você escreveO que faz
go mod init nomeCria o go.mod do módulo.
go run .Roda o pacote da pasta atual (todos os arquivos).
go buildGera o executável com o nome do módulo.
cat go.modMostra o nome do módulo e a versão do Go.

Resumo

  • go mod init nome cria o módulo, com o go.mod.
  • go run . e go build trabalham com a pasta inteira.
  • Arquivos da mesma pasta são o mesmo pacote.
