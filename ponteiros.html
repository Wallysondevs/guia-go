Ponteiros

Um ponteiro é um endereço: em vez de guardar o valor, ele guarda onde o valor mora na memória. Em Go você usa ponteiros para uma função mudar uma variável de fora e para não copiar structs grandes. Não há conta com ponteiros como em C: é bem mais seguro.

Você vai aprender
  • &x (o endereço de x) e *p (o valor no endereço).
  • Passar *int para uma função mudar a variável de quem chamou.
  • Ponteiros para structs, new e o perigo do ponteiro nil.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), na pasta ~/projetos da usuária fictícia ana, no computador notebook. As mensagens de erro do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída. A explicação em português vem ao lado.

1. & e *

package main

import "fmt"

func main() {
	x := 10
	p := &x
	fmt.Println("x =", x)
	fmt.Println("p aponta para um int:", *p)
	fmt.Printf("p tem tipo %T\n", p)

	*p = 20
	fmt.Println("depois de *p = 20, x =", x)

	var nada *int
	fmt.Println("ponteiro vazio:", nada, nada == nil)
}
$ go run main.go
x = 10

p tem tipo *int
depois de *p = 20, x = 20
ponteiro vazio: <nil> true
&x
“o endereço de x”.
p := &x
p é do tipo *int: ponteiro para int.
*p
“o valor que está no endereço p”: lê ou escreve em x.

Ponteiro sem valor é nil (aparece como <nil>): ainda não aponta para nada.

2. Para que serve

Na aula de funções você viu que os argumentos são cópias. Passando o endereço, a função consegue mudar o original. Com structs, o Go deixa escrever c.Valor mesmo quando c é ponteiro. E new(T) cria um valor zero e devolve o ponteiro:

package main

import "fmt"

func dobrar(n *int) {
	*n = *n * 2
}

type Contador struct {
	Valor int
}

func novoContador() *Contador {
	return &Contador{Valor: 100}
}

func main() {
	x := 21
	dobrar(&x)
	fmt.Println("x:", x)

	c := novoContador()
	c.Valor++ // o Go entende (*c).Valor
	fmt.Println("contador:", c.Valor)

	q := new(int)
	*q = 7
	fmt.Println("new(int):", *q)
}
$ go run main.go
x: 42
contador: 101
new(int): 7

Quando dá errado

Usar um ponteiro nil

Ler *p quando p é nil compila, mas para o programa:

package main

import "fmt"

func main() {
	var p *int
	fmt.Println("antes")
	fmt.Println(*p)
}
$ go run main.go
antes
panic: runtime error: invalid memory address or nil pointer dereference
[signal SIGSEGV: segmentation violation code=0x1 addr=0x0 pc=0x499e31]

goroutine 1 [running]:
main.main()
	/home/ana/projetos/erro-nil/main.go:8 +0x51
exit status 2

nil pointer dereference quer dizer “tentou ler o valor de um ponteiro que não aponta para nada”. Confira if p != nil antes.

Passar o valor onde se espera o endereço 
package main

import "fmt"

func dobrar(n *int) {
	*n = *n * 2
}

func main() {
	x := 21
	dobrar(x)
	fmt.Println(x)
}
$ go run main.go
# command-line-arguments
./main.go:11:9: cannot use x (variable of type int) as *int value in argument to dobrar

Chame dobrar(&x).

import "fmt"

	pontos := 50

pontos: 0

Resumo

  • &x é o endereço; *p é o valor apontado.
  • Passe ponteiros quando a função precisa mudar o original.
  • Ponteiro nil não aponta para nada: ler dele dá panic.
