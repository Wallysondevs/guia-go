panic e recover

Um panic é o programa dizendo “não dá para continuar”: índice fora do slice, ponteiro nil, divisão inteira por zero, ou um panic(…) chamado por você. Ele desfaz as funções uma a uma, rodando os defer, e encerra o programa, a não ser que um recover o segure.

Você vai aprender
  • Ler a saída de um panic: a mensagem e a pilha (goroutine 1 [running]).
  • Ver que os defer rodam mesmo durante um panic.
  • Segurar um panic com recover dentro de um defer, e saber quando não usar panic.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), na pasta ~/projetos da usuária fictícia ana, no computador notebook. As mensagens de erro do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída. A explicação em português vem ao lado.

1. Um panic de perto

package main

import "fmt"

func validarIdade(idade int) {
	if idade < 0 {
		panic(fmt.Sprintf("idade inválida: %d", idade))
	}
	fmt.Println("idade ok:", idade)
}

func main() {
	defer fmt.Println("defer da main: roda mesmo com panic")
	validarIdade(30)
	validarIdade(-1)
	fmt.Println("fim")
}
$ go run main.go
idade ok: 30
defer da main: roda mesmo com panic
panic: idade inválida: -1

goroutine 1 [running]:
main.validarIdade(0x270d90b74ea8?)
	/home/ana/projetos/panic/main.go:7 +0xc8
main.main()
	/home/ana/projetos/panic/main.go:15 +0x67
exit status 2

A saída mostra a mensagem do panic, a pilha de chamadas (quem chamou quem, com arquivo e linha) e o exit status 2. Repare que o defer da main rodou antes do programa morrer, e que fim nunca apareceu.

2. recover

O recover() só funciona dentro de uma função adiada com defer. Ele devolve o valor do panic (ou nil, se não houve panic) e faz a função terminar normalmente. Aqui ele transforma a divisão por zero num error:

package main

import "fmt"

func dividir(a, b int) (res int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("recuperado: %v", r)
		}
	}()
	return a / b, nil
}

func main() {
	fmt.Println(dividir(10, 2))
	fmt.Println(dividir(1, 0))
	fmt.Println("o programa continuou")
}
$ go run main.go
5 <nil>
0 recuperado: runtime error: integer divide by zero
o programa continuou
Panic é exceção, não controle de fluxo

Para erros esperados (arquivo que não existe, texto que não é número), devolva um error. Deixe o panic para defeitos do programa, e o recover para fronteiras, como um servidor que não pode cair por causa de uma requisição.

Quando dá errado

recover fora de um defer

Chamado direto, o recover devolve nil na hora (ainda não houve panic) e não segura nada depois:

package main

import "fmt"

func main() {
	if r := recover(); r != nil {
		fmt.Println("segurei:", r)
	}
	var lista []int
	fmt.Println(lista[0])
}
$ go run main.go
panic: runtime error: index out of range [0] with length 0

goroutine 1 [running]:
main.main()
	/home/ana/projetos/recover-fora/main.go:10 +0x1d
exit status 2

func main() {

	fmt.Println("fim")

package main

import "fmt"

func primeiro(lista []int) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("recuperado:", r)

}

func main() {
	primeiro([]int{})
	fmt.Println("fim")

Resumo

  • panic desfaz a pilha rodando os defer e encerra com exit status 2.
  • recover() dentro de um defer segura o panic.
  • Erro esperado é error; panic é para defeitos.
