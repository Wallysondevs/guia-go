Benchmarks

Um benchmark mede quanto tempo (e quanta memória) um pedaço de código gasta. Em Go, ele mora no mesmo arquivo _test.go dos testes (aula go test) e roda com go test -bench. Nesta aula você compara dois jeitos de juntar textos e vê, com números reais, por que o strings.Builder existe.

Você vai aprender
  • Escrever uma função BenchmarkXxx(b *testing.B) com for b.Loop().
  • Rodar com go test -bench=. e ler cada coluna da saída.
  • Medir memória com -benchmem (B/op e allocs/op).
  • Filtrar benchmarks e repetir medições com -count.
Sobre as saídas. Todas as saídas desta aula foram colhidas rodando o código de verdade, com Go 1.27.3 num Linux (linux/amd64), dentro de ~/projetos/go-nivel3 da usuária fictícia ana, no computador notebook. Os tempos de benchmark ficaram como saíram (são reais, mas dependem do processador e do momento): no seu computador os números serão outros. O que vale comparar é a proporção entre as linhas. As mensagens do Go aparecem em inglês, exatamente como a ferramenta escreveu: nunca traduzimos nem inventamos saída.

1. O código e os benchmarks

Duas funções que fazem a mesma coisa: juntar uma lista de textos. Uma usa +=, a outra usa strings.Builder:

package juntar

import "strings"

func ComMais(partes []string) string {
	s := ""
	for _, p := range partes {
		s += p
	}
	return s
}

func ComBuilder(partes []string) string {
	var b strings.Builder
	for _, p := range partes {
		b.WriteString(p)
	}
	return b.String()
}

No arquivo de teste, um teste comum confere que as duas dão o mesmo resultado, e dois benchmarks medem cada uma, com uma lista de 100 pedaços:

package juntar

import "testing"

var partes = make100()

func make100() []string {
	p := make([]string, 100)
	for i := range p {
		p[i] = "go"
	}
	return p
}

func TestIguais(t *testing.T) {
	if ComMais(partes) != ComBuilder(partes) {
		t.Fatal("resultados diferentes")
	}
}

func BenchmarkComMais(b *testing.B) {
	for b.Loop() {
		ComMais(partes)
	}
}

func BenchmarkComBuilder(b *testing.B) {
	for b.Loop() {
		ComBuilder(partes)
	}
}

Um go test comum roda só os testes, não os benchmarks:

$ go test .
ok  	exemplo/juntar	0.002s

2. Rodando: go test -bench=.

O -bench recebe uma expressão regular com os nomes; o . pega todos:

$ go test -bench=.
goos: linux
goarch: amd64
pkg: exemplo/juntar
cpu: Intel(R) Xeon(R) Processor
BenchmarkComMais-8      	  293248	      4152 ns/op
BenchmarkComBuilder-8   	 2663337	       450.9 ns/op
PASS
ok  	exemplo/juntar	2.424s

As quatro primeiras linhas descrevem o ambiente (sistema, arquitetura, pacote e processador). Depois, uma linha por benchmark:

PedaçoSignificado
BenchmarkComMais-8Nome do benchmark; o -8 é quantas CPUs o Go usou (GOMAXPROCS).
293248Quantas vezes o corpo do for b.Loop() rodou.
4152 ns/opTempo médio por volta, em nanossegundos (bilionésimos de segundo).

Nesta coleta, juntar com += levou cerca de 4152 ns e com strings.Builder cerca de 451 ns: umas nove vezes mais rápido.

3. Memória: -benchmem

$ go test -bench=. -benchmem
goos: linux
goarch: amd64
pkg: exemplo/juntar
cpu: Intel(R) Xeon(R) Processor
BenchmarkComMais-8      	  289062	      4140 ns/op	   10736 B/op	      99 allocs/op
BenchmarkComBuilder-8   	 2626416	       445.9 ns/op	     504 B/op	       6 allocs/op
PASS
ok  	exemplo/juntar	2.372s

Duas colunas novas: B/op (bytes reservados por volta) e allocs/op (quantas vezes pediu memória). O += pediu memória 99 vezes, porque cada soma cria um texto novo e copia tudo. O Builder cresce aos poucos e pediu só 6 vezes. Essa é a explicação da diferença de tempo.

4. Filtrando e repetindo

Para rodar só um benchmark, passe parte do nome:

$ go test -bench=Builder -benchmem
goos: linux
goarch: amd64
pkg: exemplo/juntar
cpu: Intel(R) Xeon(R) Processor
BenchmarkComBuilder-8   	 2740524	       437.4 ns/op	     504 B/op	       6 allocs/op
PASS
ok  	exemplo/juntar	1.203s

Medições variam. Com -count=2 cada benchmark roda duas vezes, e o -run=^$ pula os testes comuns (nenhum nome casa com “vazio”):

$ go test -run=^$ -bench=. -benchmem -count=2
goos: linux
goarch: amd64
pkg: exemplo/juntar
cpu: Intel(R) Xeon(R) Processor
BenchmarkComMais-8      	  277629	      4096 ns/op	   10736 B/op	      99 allocs/op
BenchmarkComMais-8      	  287457	      4046 ns/op	   10736 B/op	      99 allocs/op
BenchmarkComBuilder-8   	 2770136	       433.1 ns/op	     504 B/op	       6 allocs/op
BenchmarkComBuilder-8   	 2721852	       440.0 ns/op	     504 B/op	       6 allocs/op
PASS
ok  	exemplo/juntar	4.704s

Repare que os números mudam um pouco de uma rodada para outra, mas a proporção se mantém. Para comparar versões do seu código com estatística, a ferramenta benchstat lê várias rodadas e diz se a diferença é real.

Quando dá errado

Rodei go test e o benchmark não apareceu

Benchmarks só rodam com -bench. Sem ele, o go test só roda os TestXxx (veja a seção 1).

Números muito diferentes a cada vez

Outros programas abertos, economia de energia e aquecimento do processador mexem nos tempos. Feche o que puder, use -count e compare na mesma máquina, nunca entre computadores diferentes.

Resumo

  • Benchmarks são func BenchmarkXxx(b *testing.B) com for b.Loop(), num arquivo _test.go.
  • go test -bench=. mostra voltas e ns/op; -benchmem soma B/op e allocs/op.
  • Os números mudam de máquina para máquina: compare proporções, na mesma máquina, com -count.
